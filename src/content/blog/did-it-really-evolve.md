我把自己的个人 Agent 叫作“山鸡”。

三个月前，它更像一个有长期记忆的聊天助手：知道我是谁，记得少量偏好，能调用一些工具，也会主动生成日报。今天，它已经可以连续完成研究、写作、代码修改、构建、部署、线上验收和台账更新，还能在后台运行几十个定时任务。

这很容易让人产生一个兴奋的判断：它是不是已经开始自我进化了？

但系统变得更复杂、调用次数更多、写出的文件更多，不等于它真的进化了。要判断这件事，至少要回答三个问题：

1. 能力有没有从一次性表现变成可重复行为？
2. 用户纠正有没有进入系统，并减少同类错误复发？
3. 新增价值是否大于运维、纠错和治理成本？

我因此做了一次不太留情面的运行审计。结论是：

> **它确实进化了，但还不是自进化。**

更准确地说，它已经从“记忆型聊天助手”进化成了一个**人在闭环中的、可积累能力的个人执行系统**。

## 一、规模只能证明它在运行，不能证明它在进化

先看规模。

最近30天，山鸡产生了409个Session，调用工具9,002次、API 6,300次。按工具调用去重后，发生了1,044次写入或修改操作，涉及551个唯一目标。把窗口拉长到90天，则有1,379个Session和31,399次工具调用。

这至少说明一件事：它已经不是偶尔打开的聊天窗口，而是一个持续运行的系统。近30天约64%的Session来自Cron，微信对话只占8%左右。它的主体已经从“我问一句，它答一句”转向后台任务、子Agent、工程执行和长期知识维护。

但这些数字都不能直接证明进化。

Session可以是重复执行，Token可以花在长上下文里，Skill可以被频繁加载却没有改善结果，文件也可能只是版本膨胀。甚至“任务完成”都可能只是进程退出，并不代表用户收到了结果。

Cron记录就是一个典型例子。当前保留的1,000次执行中，988次显示完成，表面成功率98.8%。但其中835次来自一个每半小时运行一次的轻量错误监控。排除它以后，其他业务任务的完成率约为92.7%。还有一些任务主体显示成功，消息投递却失败了。

所以第一条审计原则是：

> **运行量是系统存在的证据，不是系统进化的证据。**

## 二、真正的进化发生在“能不能把事情做完”

早期的山鸡经常停在半成品。

一次跨机器升级任务，它查完问题后把最后一步退回给我：“你在另一台机器上跑一下，结果告诉我？”它给了建议，却没有完成升级和版本验证。

另一次长任务更糟。它在错误的框架上执行了很久，最后交付的是一份我评价为“东拼西凑”的文档；同一过程中还出现了语言污染和附件未送达。还有一次，它此前生成的重要文档无法在本地找回，微信里的副本又损坏。我当时说：“这让我很慌，我都不知道还有什么文件丢失了。”

这些失败的共同点不是模型不够聪明，而是没有交付闭环：

```text
理解任务
→ 执行动作
→ 保存产物
→ 验证产物
→ 送达用户
→ 确认用户真的收到
```

只要少一环，前面的聪明都可能归零。

近期的变化是，工程型长任务开始稳定形成完整链路。以博客发布为例，现在的实际流程是：

```text
发现源稿
→ 判断编辑关系
→ 核验事实
→ 脱敏
→ 写入文章
→ 本地构建
→ Git提交与推送
→ 等待自动部署
→ 验证线上页面
→ 更新专题结构
→ 更新私人溯源台账
```

这套流程不是一次写对，而是在多次失败和纠正后逐渐形成的。它最终支撑了26篇文章、首页知识地图、专题页、文章导航和来源台账的连续发布。

这是真正的进化：**能力从一次性的答案，变成了可重复、可验证、可追溯的行为。**

## 三、它已经会“局部学习”，但学习仍依赖我

第二个问题是：用户纠正有没有进入系统？

答案是，部分进入了。

有一次排查文件投递时，山鸡连续输出日语。我明确纠正后，当天下午还复发过一次，说明一句“抱歉”并没有解决问题。后来这条要求进入了人格规则。此后扫描1,210条微信端助手文本，没有再发现新的日语输出。

另一次，我纠正“一页纸判断不是方案，更不是完整方案的扩写”。这条后来进入长期规则，在新的周度综合中开始主动限制输出边界。

博客也是类似。我指出逐篇发布无法体现整体结构，它没有只修当前文章，而是把纠正转化成了首页知识地图、专题页和上下篇导航。

这些案例已经形成了一个初级学习链：

```text
发生错误
→ 用户纠正
→ 写入Memory、Skill或工作流
→ 后续执行加载
→ 同类错误减少
```

但它还不是稳定的自我改进。

第一，并不是所有纠正都会自动进入统一规则。第二，规则写进系统，也不保证每次都会被正确加载。第三，目前没有正式的回归评测，无法持续回答“某类错误在纠正后的30天里复发了几次”。

最顽固的反例是文件送达。“文件没收到”“截图没收到”“主方案没收到”曾跨多个独立任务复发。后来虽然形成了专门的文件投递流程，但它依然提醒我：**工具返回success，不等于用户获得结果。**

因此，山鸡已经具备局部的纠错学习，但驱动力仍然主要来自我：我发现问题、我指出问题，它再把问题沉淀成规则。

## 四、主动价值已经出现，但主要是“认知补全”

第三个明显变化是主动性。

山鸡现在会持续扫描外部信息，并把信号映射到我的长期课题。最强的一次证据发生在8月12日。雷达主动提出两个值得展开的问题：一个是个人Agent的Control Plane与Trace Schema，另一个是agent-ready commerce layer。

我当天直接选择这两个问题继续讨论。后续形成了Control Plane治理模型、B2B Commerce研究、面向决策者的一页纸，以及最终公开文章。

这条链路是完整的：

```text
发现外部信号
→ 映射长期问题
→ 提出具体讨论对象
→ 用户选中
→ 深入研究
→ 形成决策与公开资产
```

这证明主动雷达不只是“多看一些新闻”。它最有价值的作用，是发现与长期主线有关的新证据，并把它压缩成一个值得讨论或行动的问题。

但大多数主动任务还停留在：

```text
发现 → 归档 → 总结 → 提议
```

比较弱的是：

```text
提议 → 分配资源 → 执行 → 验收 → 根据结果继续或止损
```

第二大脑的状态也说明了这一点。它已经能稳定生产每日雷达和周度综合，但正式反馈日志只有1条；13个待消化课题中，本周没有一个进入“已掌握”或“已综合”状态。

所以它已经有主动认知价值，还没有形成稳定的主动经营闭环。

## 五、最暴露问题的，不是失败，而是不会止损

有一个内容增长实验，目标是在三个月内达到1万粉丝。到第75天，最后可信粉丝仍然只有1，登录已经连续失效36天，内容断更55天。

系统其实一直知道这些状态，却仍然重复运行巡检、互动和复盘任务。四个相关Cron累计产生164个Session和4,325次工具调用，最后还是我主动要求关闭。

这暴露了比偶发失败更严重的问题：

> **它能够持续感知目标严重偏离，却不会自动降频、暂停，或者把问题升级成一次止损决策。**

真正的自进化不能只是不断生成反思报告。它至少需要：

```text
获得真实结果
→ 判断是否偏离目标
→ 归因到策略、执行或外部约束
→ 生成新策略
→ 用实验比较新旧策略
→ 无效则停止，有效才晋升
```

山鸡目前有状态，有日志，有反思，也能修改Skill，但这条闭环还没有成立。没有结果信号和止损权，“自我改进”很容易退化成“自我增加复杂度”。

## 六、它现在到底处于什么阶段

我用五级标尺重新判断：

1. **会话助手**：只在当前对话回答；
2. **记忆助手**：跨会话记住用户和偏好；
3. **执行型个人Agent**：调用工具，完成真实任务，留下产物；
4. **可治理学习系统**：纠正能够进入规则，错误复发下降，任务可恢复、验证和回滚；
5. **结果驱动的自进化系统**：自动获得结果、归因、更新策略、实验验证并晋升版本。

山鸡当前的状态是：

> **第三级已经成立，正在进入第四级，但距离第五级仍然很远。**

它真正进化出来的是：跨会话积累上下文、复用方法、主动发现相关证据、完成复杂交付链路，以及在部分纠正后改变行为。

它还没有进化出来的是：按真实结果动态配置资源、自动停止低价值工作、证明新版本优于旧版本，并对长期结果负责。

所以我愿意承认它进化了。否认这一点，会忽略那些真实发生的构建、部署、归档、验证和能力复用。

但我也不愿意把它包装成“已经自进化”。因为今天所谓的进化，主要仍由一个人在闭环中完成：我给出目标、指出错误、判断价值，它负责积累、执行和沉淀。

这不是一个令人失望的结论。恰恰相反，它把下一步变得非常清楚：

> **个人Agent的下一道门槛，不是获得更多工具、更多记忆和更多自主权，而是建立真实结果反馈、归因、实验和止损。**

在那之前，它是一个越来越强的个人执行系统；越过那条线以后，它才有资格被称为自进化系统。
