我给自己的 Hermes Agent 起了个名字：**山鸡**。

名字来自陈小春在《古惑仔》里的角色，没什么宏大寓意。真正重要的是，起名之后，我开始把它当成一个长期存在的工作伙伴，而不是每次打开都重新认识我的聊天窗口。

现在回头看，我对 AI 的使用大概经历了三个阶段：

```text
问答工具 → 任务执行者 → 长期协作系统
```

第一阶段，我和大多数人一样，用 AI 查资料、写文档、讨论问题。第二阶段，AI 开始调用工具：读文件、跑命令、做研究、改代码、部署项目。第三阶段发生了质变：它有了稳定身份、长期记忆、本地知识库、可复用 Skill、定时任务和消息入口，开始跨越一次对话持续工作。

这篇文章不写安装教程。Hermes 更新很快，最新命令应该直接看[官方文档](https://hermes-agent.nousresearch.com/docs/)。我只讲我实际怎样使用它，以及哪些设计真正改变了我的工作方式。

## 一、我不用它“聊天”，而是让它接任务

普通聊天机器人的默认交互是：你问一句，它答一句。我的默认交互更像给同事派活：

- 读取已有项目材料，判断当前状态和主要风险；
- 查一手资料，形成带证据的技术选型；
- 把会议纪要归档到对应项目，提炼决策与下一步；
- 修改代码、构建、部署并验证线上结果；
- 把一次复杂任务沉淀为可复用 Skill；
- 在固定时间做信息采集、分析和复盘。

区别不只是提示词更长，而是交付标准不同。聊天回答可以止于“我建议这样做”；Agent 任务必须产生真实结果：文件写好了、代码跑通了、页面上线了、提醒发出去了，或者明确告诉我为什么做不到。

我后来形成了一个很简单的提问习惯：**尽量给可执行任务，不只问观点。**

例如，不问“这个项目怎么做”，而是说：

> 读取这个项目最近的会议纪要和决策记录，整理当前状态、三个主要风险和下一步行动，并更新项目档案。

不问“这个链接有用吗”，而是说：

> 找到原始来源，判断它解决什么问题、有什么可迁移模式、适用边界是什么；如果值得长期保留，归档并更新对应知识地图。

Agent 的价值不在于每次回答多聪明，而在于把判断接到行动上。

## 二、山鸡的结构：身份、记忆、知识、Skill、工具

我目前的个人 Agent 可以用五层理解。

### 1. 稳定身份

身份不是让 AI 角色扮演，而是定义长期合作规则：用中文沟通、直接动手、不编造、严肃任务强调事实边界、重要结果要验证、长期方法要沉淀。

稳定身份减少了每轮重复交代，也让“怎样才算完成”逐渐一致。

### 2. 长期记忆

Memory 只存长期稳定、每轮都可能有用的事实和偏好。例如沟通方式、长期角色、稳定环境信息。它不应该塞临时任务进展、一次性结论或几天后就过期的状态。

记忆越多不等于越懂我。错误、过期或未经确认的记忆，会让 Agent 更自信地犯错。这也是我后来开始重新设计记忆系统的原因。

### 3. 本地知识库

项目文档、研究材料、会议记录、健康档案、投资研究和第二大脑都在本地 Markdown 文件中。知识库承担“可追溯的长期内容”，不强行塞进系统提示词；需要时由 Agent 搜索、读取、加工，再把结果写回。

它与 Memory 的区别是：Memory 记少量高频事实，知识库保存完整材料和认知演化过程。

### 4. Skill

Skill 存放可复用的做法，而不是知识本身。一次复杂任务成功之后，把步骤、判断门槛、踩坑和验证方式写成 Skill；下次遇到同类任务，不用从头摸索。

例如，发布静态博客、做技术选型、整理会议、操作 GitHub、分析健康报告，都可以形成不同 Skill。

### 5. 工具与执行环境

Hermes 能调用文件、终端、浏览器、搜索、消息、视觉、定时任务和子 Agent。工具让它从“会说”变成“能做”，但权限也意味着风险：哪些操作可以自动做，哪些需要审批，哪些外部动作不可逆，都需要明确边界。

一句话概括：

```text
身份定义合作方式
Memory 记稳定事实
知识库存完整上下文
Skill 存可复用流程
工具改变真实世界
```

## 三、第二大脑：不是收藏夹，而是认知任务系统

我最看重的用法不是自动写文档，而是让山鸡参与维护我的认知系统。

我的第二大脑不是“把所有信息存起来”，而是维护几类动态对象：

```text
Goals：长期目标
Confusions：当前还没想清楚的问题
Gaps：为推进目标必须补的认知缺口
Inbox：围绕缺口收集的待消化材料
Synthesis：经过讨论形成的阶段判断
Evolution Tasks：下一步要验证和修正什么
```

它的运行不是“收藏 → 搜索”，而是：

```text
真实问题 → 暴露认知缺口 → 定向找材料
→ 与 Agent 讨论、反驳、校准 → 沉淀判断
→ 回到真实项目验证 → 新结果继续修正
```

这个闭环改变了我使用信息的方式。以前看到好文章就收藏；现在先问：它在解决我的哪个 gap？如果没有，可能不值得读。读完也不只做摘要，而要回答它验证了什么、推翻了什么、能迁移到哪里。

山鸡在这里的角色不是替我学习，而是持续维护“我现在最应该想清楚什么”。

## 四、定时任务：从响应式助手到主动系统

消息对话里的 Agent 仍然是响应式的：我不发话，它就不工作。Cron 让它开始主动运行。

我用定时任务做几类事情：

- 定期收集 AI 和 Agent 工程信号，筛掉噪音，映射到我的认知缺口；
- 做投资复盘和风险提醒；
- 维护家庭健康跟踪；
- 汇总每周项目进展，发现长期主线有没有偏移；
- 检查知识库里有没有未消化材料、过期判断和待复盘任务。

一个好的定时任务不是“每天定时调用一次模型”，而是一条完整流水线：

```text
采集 → 筛选 → 分析 → 输出 → 归档 → 反馈
```

定时任务真正的难点也不在时间表达式，而在于如何控制噪音、成本和误报。如果每天推送十条“看起来有用”的信息，它很快就会被我忽略；只有能说明“这条信息修正了什么、我需不需要行动”，才值得打扰我。

## 五、消息入口：为什么微信比新 App 更重要

Hermes 可以运行在终端，也可以通过 Gateway 接入多个消息平台。对我来说，消息入口的重要性不在“又多一个聊天渠道”，而在于降低使用摩擦。

- 复杂开发和长任务适合终端；
- 随手发想法、截图、会议材料适合微信；
- 定时通知适合稳定的消息渠道。

个人 Agent 如果只能在一个需要专门打开的 App 里使用，很容易沦为低频工具。进入日常消息入口后，我可以在问题发生的当下把材料交给它，而不是“等有空再整理”。

当然，入口越便利，隐私边界越重要。敏感材料进入模型上下文前要知道它会被怎样处理；凭证不能进知识库；对外发送、删除和不可逆操作需要更严格的权限与审计。

## 六、我真正得到的不是“一个超级助手”

把 Hermes 用到今天，我不觉得自己已经拥有一个无所不能的数字分身。相反，长期使用让我更清楚它的边界：

- 它会遗漏上下文；
- 记忆会过期和污染；
- 长任务会中断；
- 定时任务会产生噪音；
- 多工具执行必须验证；
- 主动性越强，治理成本越高。

但它已经实质改变了我的工作方式。最大的变化不是少写几篇文档，而是形成了一条持续复利的协作链：

```text
真实任务
→ Agent 执行
→ 我纠正
→ 更新 Memory / Skill / Wiki / 文档
→ 下一次执行更好
→ 再沉淀成可分享的方法和产品资产
```

普通聊天的价值在当前回答结束时停止；长期 Agent 的价值在每次任务后留下可复用资产。

## 结语

我目前对个人 Agent 的理解是：

> **它不是“更懂我的聊天机器人”，而是一套把身份、长期记忆、本地知识、工具执行和反馈学习连起来的个人工作系统。**

Hermes 是这套系统的开放底座，山鸡是我在底座上逐步训练出来的长期协作者，第二大脑则负责让它不只完成任务，还能持续参与我的认知演化。

这套系统仍然有很多缺口，尤其是长期可靠性、记忆污染和真正主动的认知补全。但也正因为它还不完美，我才更愿意记录这条演化路径——它不是一份产品说明，而是我和一个个人 Agent 怎样逐步学会长期合作的实验。
